Why it exists

700 ms spikes in the middle of a match.

It started with a laptop with a MediaTek MT7925 Wi-Fi 7 card that kept freezing in Fortnite. The internet was fine. The culprits were the card's power saving and roaming scans, both on by default.

NetTune turns that diagnosis into a repeatable tool: test, fix the few settings that matter, test again, and show you the difference in numbers.

What it tweaks

Only settings with a real effect on latency.

Applied on every physical adapter: Wi-Fi, Ethernet and USB. Option names are recognized in English, Portuguese and Spanish drivers.

Wi-Fi power plan

"Wireless Adapter Settings" set to maximum performance, so gaming on battery stops causing spikes.

No sleeping adapter

"Allow the computer to turn off this device" off, via PnPCapabilities = 24. Takes effect after a restart.

Adapter power saving off

The card stops dozing between packets, which is what makes it slow to wake up mid-game.

Roaming at lowest

No more scanning for other access points during a match. Every scan freezes the connection.

Green Ethernet & EEE off

Energy-Efficient Ethernet causes the same problem on the cable. USB selective suspend goes too.

RSC off

Receive Segment Coalescing merges packets to save CPU. Great for downloads, bad for latency.

Fastest DNS, only if it wins

Tests Cloudflare, Google, Quad9 and OpenDNS with uncached queries and switches only when one clearly wins.

Backup & revert

Every original value is saved to JSON before anything changes. -Mode Revert puts it all back.

What it does not do, on purpose

No miracle tweaks.

A lot of "gaming network optimizers" change dozens of settings that do nothing for in-game ping. NetTune skips them.

×

TCP tweaks

Nagle, TcpAckFrequency, TCPNoDelay: games use UDP, so these change nothing in a match.

×

NetworkThrottlingIndex & co.

No evidence they improve ping, and some make other things worse.

×

"DNS lowers your ping"

DNS only turns names into IPs before connecting. Faster logins and stores, yes. In-game ping, no.

×

VPNs, virtual adapters, Bluetooth

Left untouched and ignored, so nothing else on your PC breaks.

How it works

Measure. Fix. Prove it.

Measure

50 pings to your router, DNS and the closest Epic, Valve, Blizzard, Ubisoft, Xbox and Embark servers: average, jitter, spikes and loss.

Back up

The current value of every option it may touch is saved, including the old DNS for IPv4 and IPv6.

Apply

Only the settings above, read back afterwards. A ✓ means it really changed.

Measure again

Same servers, fair comparison: ▼ when it improved, ▲ when it got worse.

Straight from the console.

Usage

One script. Four commands.

Open Windows PowerShell as administrator (the blue one, 5.1) in the folder where you saved NetTune.ps1.

Restart after Apply and after Revert. The "allow the computer to turn off this device" option only changes after a restart. NetTune tells you at the end.
The connection drops for a few seconds during Apply while the adapters restart.
1 · Measure only · changes nothing, no admin needed
PS> powershell -ExecutionPolicy Bypass -File .\NetTune.ps1
2 · Dry run · shows what would change
PS> powershell -ExecutionPolicy Bypass -File .\NetTune.ps1 -Mode Apply -WhatIf
3 · Apply · measure, back up, apply, measure again
PS> powershell -ExecutionPolicy Bypass -File .\NetTune.ps1 -Mode Apply
4 · Undo everything · uses the latest backup
PS> powershell -ExecutionPolicy Bypass -File .\NetTune.ps1 -Mode Revert

More options: -Dns Keep, -Services Epic,Valve, -ExtraTargets 1.2.3.4, -Count 100. Full help: Get-Help .\NetTune.ps1 -Full

FAQ

Questions.

Is it safe to run?

Yes. Run the measure-only mode or -WhatIf first to see exactly what would change. Apply saves a backup of every original value before touching anything, and -Mode Revert restores it.

Will it lower my ping to the game server?

It removes the spikes and lag that come from your own PC and Wi-Fi. It cannot shorten the distance to the server or fix your ISP. The golden rule: if the ping to your router is high or spiky, the problem is local, and that is exactly what NetTune fixes.

Why didn't the "after" test show the power-management change?

"Allow the computer to turn off this device" only takes effect after a restart, so the after test can't include it yet. Restart the PC after Apply.

The spikes came back after a driver update. Why?

Driver updates (Windows Update, Lenovo Vantage and similar) can restore factory values. Just run -Mode Apply again.

I get an execution policy error.

Always launch it with powershell -ExecutionPolicy Bypass -File ... as in the examples. It is built for Windows PowerShell 5.1 and also runs on PowerShell 7.

Stop guessing. Measure.

One free script, about two minutes, and you'll know whether the lag is your PC or the internet.
