01 · Story

700 ms spikes, mid-match.

It started with a Wi-Fi 7 laptop that froze in Fortnite. The internet was fine. The card's power saving and roaming scans were on by default, napping between packets and hunting for other routers mid-fight. NetTune turns that diagnosis into a tool: test, fix the few settings that matter, test again.

02 · New in 1.7.0

More measured. Still honest.

An MTU test, the TCP Optimizer set with honest labels, and a test that carries on by itself after the restart. Release notes ↗

01

Automatic MTU test

Don't Fragment pings with a binary search to 1.1.1.1, 8.8.8.8 and 9.9.9.9. Every step is retried, and the result is confirmed: 5 of 5 pings pass and one byte more always fails. The MTU only changes if 1500 doesn't fit on your network. Skip it with -NoMtu.

02

Carries on after the restart

Answer y to "Restart now?" and NetTune saves the "before" test, then runs once at your next logon. It waits for the network, warns if you are on a different one, and shows a Before vs After that includes the registry values.

03

Nagle stays on Wi-Fi

Windows rebuilds the Wi-Fi adapter's TCP/IP settings on every network change, wiping the Nagle values. NetTune writes them to every network, and a small SYSTEM task writes them again whenever a network connects. Revert removes the task and every value.

04

The TCP Optimizer set, labeled

TCP globals, offloads, Nagle, MMCSS and registry values, on by default. Each one is marked with what it really changes: see the table. Skip them all with -NoTcp.

05

Every change read back

✓ when it stuck, ✗ when it didn't, ! when your Windows keeps it read-only. The backup now covers everything, including values that didn't exist before, so Revert deletes them.

06

Visible progress

A live status line during the region search and the MTU test. MTU rows appear as soon as each target finishes, so it never looks stuck.

Fixes

03 · Latency fixes

The fixes that move ping.

Always applied, to every physical adapter: Wi-Fi, Ethernet and USB. Driver options are found by their registry keyword, so they're recognised in any Windows language.

01

Wi-Fi power plan

"Wireless Adapter Settings" set to maximum performance, so gaming on battery stops causing spikes.

02

No sleeping adapter

"Allow the computer to turn off this device" off, via PnPCapabilities = 24. Takes effect after a restart.

03

Adapter power saving off

The card stops dozing between packets, which is what makes it slow to wake up mid-game.

04

Roaming at lowest

No more scanning for other access points during a match. Every scan freezes the connection.

05

Green Ethernet & EEE off

Energy-Efficient Ethernet causes the same problem on a cable. USB selective suspend goes too.

06

An MTU that fits

Measured on your network. Changed only if it can't carry 1500, which is when big packets get fragmented or dropped.

07

Fastest DNS, only if it wins

Tests Cloudflare, Google, Quad9 and OpenDNS with uncached queries and switches only when one clearly wins. Faster lookups, not lower ping.

08

Backup & revert

Every original value is saved to JSON before anything changes. -Mode Revert puts it all back.

05 · What it won't do

No miracle promises.

Most "gaming network optimizers" flip dozens of settings and promise lower ping. NetTune tells you what each one really changes.

"TCP tweaks lower your ping"

Games use UDP. The TCP Optimizer set is included because people ask for it, labeled with what each setting really changes. -NoTcp skips it.

Chimney, NetDMA, DCA

Obsolete, and they give errors on Windows 11. Not included.

"DNS lowers your ping"

DNS only turns names into IPs before you connect. Faster logins and stores, yes. In-game ping, no.

Touching VPNs or Bluetooth

Virtual adapters, VPNs and Bluetooth are ignored, so nothing else on your PC breaks.

06 · How it works

Measure. Fix. Prove it.

01

Measure

50 pings to your router, DNS and the closest Epic, Valve, Blizzard, Ubisoft, Xbox and Embark servers: average, jitter, spikes and loss. Then the DNS and MTU tests.

02

Back up

The current value of every option it may touch is saved, including your old DNS for IPv4 and IPv6, and values that didn't exist yet.

03

Apply

Every change is read back: ✓ when it stuck, ✗ when it didn't, ! when your Windows keeps it read-only.

04

Measure again

Same servers, fair comparison: ▼ when it improved, ▲ when it got worse. Restart with y and it measures again after you log in, registry included.

08 · Usage

One script. Four commands.

Blue PowerShell, as adminOpen Windows PowerShell 5.1 as administrator in the folder where you saved NetTune.ps1. Test mode and the -WhatIf dry run also work without admin.

Restart after ApplyThe registry values (Nagle, MMCSS, Tcpip, ServiceProvider) and "Allow the computer to turn off this device" only take effect after a restart. Answer y to "Restart now?" and NetTune carries on by itself after you log in.

DNS on Wi-Fi is per networkWindows keeps Wi-Fi DNS for each network, so Revert restores the DNS of the network you're connected to when you run it. Ethernet isn't affected.

Expect a short dropThe adapters restart once, all together, so the connection goes away for a few seconds.

Windows PowerShell · Administrator
# 1 · Measure only. Changes nothing, no admin needed
PS> powershell -ExecutionPolicy Bypass -File .\NetTune.ps1
# 2 · Dry run. Shows what would change (no admin needed)
PS> powershell -ExecutionPolicy Bypass -File .\NetTune.ps1 -Mode Apply -WhatIf
# 3 · Apply, as admin. Measure, back up, apply, measure again
PS> powershell -ExecutionPolicy Bypass -File .\NetTune.ps1 -Mode Apply
# 4 · Undo everything, from the latest backup
PS> powershell -ExecutionPolicy Bypass -File .\NetTune.ps1 -Mode Revert

09 · FAQ

Questions, answered.

Is it safe to run?

Yes. Run the measure-only mode or -WhatIf first to see exactly what would change. Apply saves a backup of every original value before touching anything, and -Mode Revert restores it.

Will it lower my ping to the game server?

It removes the spikes and lag that come from your own PC and Wi-Fi. It can't shorten the distance to the server or fix your ISP. The golden rule: if the ping to your router is high or spiky, the problem is local, and that's exactly what NetTune fixes.

Why doesn't the "after" test show everything?

The registry values (Nagle, MMCSS, Tcpip, ServiceProvider) and "Allow the computer to turn off this device" only take effect after a restart, so the after test can't include them yet. Answer y to "Restart now?" at the end of Apply: NetTune runs the test once more after you log in, with a Before vs After that includes them.

Do the TCP tweaks lower my in-game ping?

Mostly no: games use UDP. The table above files each one under what it really changes: small or indirect, TCP only (downloads, sites, launchers) or no real effect. They're included for parity with TCP Optimizer, and -NoTcp skips them all.

I switch between Wi-Fi networks. Anything to know?

The Nagle values are kept on every network by a small scheduled task. The DNS on Wi-Fi is per network, so Revert only restores it on the network you're connected to. And the MTU depends on the network too: run NetTune again when you change networks.

The spikes came back after a driver update. Why?

Driver updates (Windows Update, Lenovo Vantage and similar) can restore factory values. Just run -Mode Apply again.

I get an execution policy error.

Always launch it with powershell -ExecutionPolicy Bypass -File ... as in the examples. It's built for Windows PowerShell 5.1 and also runs on PowerShell 7.
